# 이동 오류 수정 보고서

## 원인

API와 Docker는 정상 응답했지만 Fabric 경로 실행과 원목 후보 선택에 문제가 있었다.
HTTP 200은 요청 처리 완료이며 목표 달성을 뜻하지 않는다.

1. **과도한 충돌 범위**: 몸 너비에 좌우 각각 0.15블록을 추가해, 정상적으로 잎 옆에 서 있어도
   확대된 몸체가 잎 영역에 겹치면서 unsafe_start가 발생했다.
2. **감속 없는 경유점 전환**: 거리 0.18 이내면 속도와 관계없이 다음 경유점으로 전환했다.
   회전 시 남은 관성으로 경로에서 벗어나고, 확대된 충돌 영역이 장애물과 겹쳐 중단했다.
3. **원목 높이 선택 제한**: wood는 발 높이+1까지만 골랐다. 아랫부분을 캔 나무의 남은 원목이
   approach의 도달 높이 안에 있어도 후보에서 제외됐다.
4. **진단 표시 부족**: 거절한 블록·검사 종류가 없고, 목표 결과가 방대한 원본 관측 뒤에 묻혔다.

인접 지지층이 실제로 비어 있는 경우도 있었으므로 모든 거절이 오검출은 아니다.
구멍·물·단차·실제 충돌 검사는 유지한다. MaxActions 1에서 접근 완료 후
채굴 전에 action_budget_exhausted로 멈추는 것은 정상이다.

## 수정

- 실제 플레이어 몸 너비를 사용하고 접촉 오차 0.00001블록만 안쪽으로 보정.
- 전진 키 해제 시점을 잔여 속도와 바닥 마찰에 따라 결정.
- 경유점 0.12블록 이내, 수평 속도 0.025 이하일 때 다음 경유점으로 전환.
- 위치나 속도를 직접 바꾸지 않고 바닐라 이동·마찰을 사용.
- safetyFailure에 검사 이유·블록·좌표·이동 구간을 기록.
- 원목 후보를 발 높이+2까지 허용하고 발 아래 원목 및 그보다 높은 수관은 제외.
- wood 최상위 결과에 actionReason/safetyFailure 추가.
- PowerShell 기본 출력을 목표·단계 결과로 줄이고 -FullRecord로 원본을 제공.

## 검증

과거 합성 회귀는 잎 접촉·실제 충돌 유지·조기 회전 방지·모서리/직각 경로 감속과 원목 높이·실패 이유 보존을 검사했다.
지면 가속·마찰 시뮬레이션은 전체 게임 물리를 대체하지 않는다. 최신 자동 시험 수는 [진행 상태](PROGRESS.md)를 따른다.

모델 호출 없이 실제 서바이벌 테스트 월드에서 다음을 확인했다.

| 시험 | 결과 |
|---|---|
| 이전에 unsafe_start가 발생하던 위치에서 드롭 수집 | pickup_verified, 이벤트 1 / 인벤토리 +1 / 검증 1 |
| 두 번째 드롭 수집 | pickup_verified, 이벤트 4 / 인벤토리 +4 / 검증 4 |
| approach→mine→collect 전체 연결 | 세 단계 completed, log_inventory_increased, 인벤토리 +1 |

공개 문서에는 원본 에피소드 ID나 전체 월드 관측을 싣지 않는다.
일반화한 회귀 조건과 수량 증거만 유지한다. 모든 지형과 서버 환경을 검증한 것은 아니다.

## 재확인

[원목 목표 시험](WOOD_GOAL.md)에서 log_inventory_increased와 inventoryDelta>=1을 확인한다.
실패 시 actionReason/safetyFailure로 실제 경로 제한을 구분한다.
