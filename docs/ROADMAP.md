# 개발 계획

기준일: 2026-09-12. 현재 검증 결과는 [진행 상태](PROGRESS.md), 후속 작업의 범위와 완료 기준은 이 문서를 따른다.
엔더 드래곤 격파와 인간·AI 협업의 전체 단계는 [MASTER PLAN](MASTER_PLAN.md)을 따른다.
이 문서의 P0–P6는 근거리 개발 우선순위이며, 전체 서바이벌 진행 단계 S0–S9 및 협업 M0–M4와 구분한다.
목표는 검증된 원목 획득 스킬을 출발점으로, 호출 예산 안에서 서바이벌 목표를 선택하고 수행하는 에이전트다.

## 현재 출발점

Fabric 1.21.1 관측·동작, docker/에 통합한 브리지와 Python 에이전트, Astra 단일 계획 호출,
최대 3행동/60초의 모델 없는 wood 스킬이 있다. 실제 월드에서 접근→채굴→획득을 확인했다.
wood@1.1.0의 등록 정의는 Git, 실행 기록은 로컬 볼륨에 보존한다.
단거리 평지 외 경로, 제작, 자동 스킬 학습과 커리큘럼은 아직 없다.

### P0. 소스 보존과 재현성

소스·테스트·lockfile·설정 템플릿·실행 도구를 `docker/`에 통합했다.
운영 설정은 docker/.env로 통일하며 Git에서 제외한다. -EnvFile은 별도 실험용 선택 기능이다.
새 설치도 같은 파일을 생성한다. 모드 설정 기본 경로는 저장소의 run/config다.
격리된 compose.smoke.yaml로 운영 월드·볼륨·실제 API 키 없이 연결 시험을 재현했다.
기존 프로젝트 이름과 데이터 볼륨은 유지한다. 기존 외부 소스 폴더는 삭제하지 않고 이관 백업으로 남긴다.

Java 빌드·Python/Node 테스트·격리 연결 시험을 CI에 추가하고 로컬 공통 실행기를 검증했다.
CI는 실제 API 키·월드·유료 호출을 사용하지 않는다. [CI 동작과 재현](CI.md)을 따른다.
사용자가 GitHub CI 두 작업과 보고서의 성공을 확인했다. 새 컴퓨터에서의 전체 설치 확인은 남아 있다.

### P1. 중단과 검증을 먼저 안정화

별도 취소 경로와 action ID·세션 기반 입력 해제 확인을 구현했다.
목표 취소 플래그는 다음 행동을 막으며 완료 경합·반복 취소·응답 유실을 자동 테스트한다.
Python 88개·Node 18개·Java 27개와 합성 취소 연결 시험을 통과했다.
실제 월드에서의 채굴·이동·목표 취소 확인은 [취소 테스트](CANCELLATION.md)를 따른다.

메뉴·죽음·차원 전환·연결 단절·요청 중복·오래된 관측·인벤토리 동기화 지연을 테스트한다.
실게임에서는 벽 접촉, 직각 회전, 막힌 경로, 단차·물, 움직이는 드롭을 따로 재현한다.
공개 회귀 자료에는 합성 관측과 최소 재현 조건만 넣고 실제 월드 로그는 로컬에 보관한다.
다음 기능으로 넘어갈 기준은 취소 확인과 실패 이유가 일관되고, 동일 실패가 자동 테스트로 잡히는 것이다.

### P2. 검증된 스킬을 데이터로 관리

wood를 코드 기반 등록 구조로 분리하고 조회·조건 검사·버전 지정 실행을 구현했다. 현재 버전은 1.1.0이다.
입력 거절·버전 불일치·증거 검증·취소·기존 명령 호환을 자동 테스트한다. [사용법](SKILLS.md)을 따른다.

스킬에 ID·버전·입력 스키마·필요 capability·선행 조건·행동/시간 예산·성공 판정 함수를 두었다.
실행 기록에는 스킬 버전, 종료 이유, 인벤토리 변화, 관측 스키마 버전을 저장한다.
처음에는 명시적 ID 조회와 조건 필터로 충분하다. 임베딩 검색은 스킬 수와 검색 실패가 늘 때 도입한다.
완료 조건은 같은 버전의 스킬을 반복 실행하고, 코드 생성 없이 결과를 비교할 수 있는 것이다.

### P3. 이동 범위 확장

수집 정지 위치 재탐색과 실행 전 no_flat_path 거절 후보 교체를 구현했다. 두 분기의 실게임 재현이 남아 있다.
정체 복구와 드롭 위치 재관측에도 각각 예산을 부여한다. 다음으로 높이 1블록 이동을 별도 행동으로 검증한다.
물·낙하·미로드 공간은 계속 구분하고, 실패를 없애기 위해 충돌·지지 검사를 끄지 않는다.
장거리 탐색은 구간별 재관측과 돌아갈 위치 기록이 확보된 다음 추가한다.

### P4. 첫 제작 목표

2026-09-13: S1 첫 단위인 직접 핫바 슬롯 선택을 구현하고 자동 검증했다. [인벤토리 규약](INVENTORY.md)을 따른다.
사용자가 실게임 슬롯 변경 성공을 확인했다. 2×2 판자·막대·작업대 제작을 구현했고 실게임 검증은 남아 있다.
[제작 테스트](CRAFTING.md) 성공 후 작업대 설치와 3×3 제작으로 확장한다.
인벤토리 슬롯 선택과 도구 장착, 제한된 레시피 제작, 작업대 설치/상호작용을 순서대로 추가한다.
바닐라 상호작용을 사용하고 서버가 반영한 재료 감소와 산출물 증가로 성공을 판정한다.
재료 부족·공간 부족·화면 종료·도구 변경은 실패로 기록하고 무한 재시도하지 않는다.
첫 완료 목표는 원목 획득→판자→작업대→나무 도구이며 이후 돌 도구로 확장한다.

### P5. Astra를 실행기 위의 선택기로 사용

모델은 관측 요약과 등록된 스킬 목록에서 다음 목표/스킬을 선택한다.
모델 출력은 구조화 스키마로 검증하고 실제 행동은 기존 결정적 실행기를 통과한다.
모델 호출 수, 출력 토큰, 총 시간, 행동 수, 실패 재시도 수에 상한을 둔다.
사용량을 수집하고 비용 추정과 실제 사용량을 구분한다. 무제한 유료 루프를 기본값으로 두지 않는다.
목표 성공 판정은 모델의 자연어 평가가 아니라 상태 비교와 스킬 검증기로 수행한다.

### P6. Voyager 방식 확장

스킬 성공률·선행 조건·최근 실패를 바탕으로 달성 가능한 다음 목표를 선택한다.
실패 피드백은 버전이 있는 스킬 수정 제안으로 만들고 회귀 테스트 후 채택한다.
임의 생성 코드를 도입한다면 호스트 파일·키·네트워크 접근을 분리한 별도 실행 환경을 먼저 마련한다.
평가에는 고정된 재현 조건, 시도 수, 성공률, 평균 행동/호출 수, 사망·중단 횟수를 기록한다.
한 월드의 한 번 성공을 일반적인 생존 능력으로 해석하지 않는다.

## 다음 한 번의 작업 범위

사용자가 실제 게임의 취소 명령 성공을 확인했다. P2의 버전별 등록 구조를 구현했다.
이번 변경의 GitHub CI도 Push 후 확인한다. P3의 수집 정지 위치 재탐색과 제한된 대체 후보 선택을 구현했다.
대체 시도도 원래 행동·시간 예산을 공유하고 세션 변화·체력 감소·취소 시에는 재시도하지 않는다.
1.0.0의 접근·채굴 후 collect=no_flat_path 사례를 수정했고, 후속 1.1.0의 획득 성공 3건을 확인했다.
합성 재현과 수정은 [수집 경로 보고서](COLLECTION_PATH_FIX.md)를 따른다.
다음 확인은 search.passes=2 수집과 다른 후보 선택을 실제 월드에서 재현하고, 재탐색 중 취소도 확인하는 것이다.
원목 높이·거리 범위 밖 중단은 [진단 문서](WOOD_FAILURE_DIAGNOSIS.md)에 정리했다.
S0 검증 후 제작의 첫 단계인 슬롯 선택·판자·작업대·나무 도구를 구현하고,
높이 1블록 이동을 별도 예산과 안전 조건으로 교차 개발한다. 이후 식량·회복과 전용 서버 검증을 연결한다.
장시간 모델 기반 실행은 MASTER PLAN의 S5에서 예산과 복구를 갖춘 뒤 진행한다.
각 작업은 코드·검증·사용법·제약을 함께 갱신하고 독립적으로 검토 가능한 커밋 단위로 마무리한다.
