## 바로 다음 작업

1. `craft_tool`의 중단 예외를 실행기와 통일하고, API 조회/실행에서 재료 부족·상태 변화가 구조화된 실패로 반환되는지 검사한다.
2. 기존 도구 재사용과 신규 제작, 지정 슬롯과 실제 선택 슬롯의 의미를 정한다. `skill-check`에 실행 입력을 반영하고 성공 검증·설명·회귀 시험을 함께 맞춘다.
3. 돌 곡괭이 직접 제작과 `craft_tool`을 실게임 확인한다. 재료 감소·도구 증가·핫바 이동·선택을 각각 기록하고 취소·부족 재료·기존 도구 분기를 확인한다.
4. 나무 도구로 돌 채굴·조약돌 수집을 연결한 뒤, 원목부터 도구 장착까지의 선행 자원 목표를 만든다. 개별 스킬의 3행동 제한을 무작정 늘리지 않는다.
5. 수집 반경 확대·대체 후보를 실제 월드에서 재현하고 새 컴퓨터 설치 및 해당 코드의 원격 CI를 확인한다.

## 후속 설계 기준

- 모델은 허용된 목표/스킬을 선택하고 실제 행동과 성공 판정은 결정적 실행기에서 처리한다.
- 재시도는 실패 유형을 구분하고 원래 예산을 공유한다. 취소·체력 감소·세션 변화에 후보 재시도를 적용하지 않는다.
- 높이 1블록 이동→왕복 경로·관측 지도→식량·회복→전투·장비→장시간 목표 순으로 범위를 확장한다.
- 장시간 실행에는 체크포인트·현재 상태 대조·전체 비용 예산을 먼저 갖춘다. 무제한 유료 루프를 기본값으로 두지 않는다.
- 스킬 개선은 실패 기록→수정 제안→격리 회귀→버전 등록 순서로 한다. 자동 생성 코드 실행은 별도 격리 설계가 필요하다.
- 완료 기록에는 구현·자동 시험·실게임 확인을 구분하고, 성공률·시간·행동/호출 수·사망·개입을 남긴다.

달력 일정과 전체 완료율은 산정하지 않는다. 아직 실게임 평가량과 후반 구현량의 근거가 부족하다.
