# 전체 계획 — 엔더 드래곤 격파와 협업

대상: Minecraft Java 1.21.1 Survival. 2026-09-25 문서 정리 기준.
아래는 장기 목표와 제안된 평가 기준이며 달성 실적이 아니다.
현재는 S0·S1 일부 구현 단계다. [진행 상태](PROGRESS.md)와 [다음 개발 계획](ROADMAP.md)을 함께 따른다.

## 목표와 평가 조건

| 목표 | 첫 완료 기준 | 후속 품질 목표 |
|---|---|---|
| G1 단독 격파 | 새 월드에서 자원 확보→엔드 진입→드래곤 처치 | 고정한 미학습 시드 5개 중 3개 이상 성공 |
| G2 인간과 협업 | 인간 1명·AI 1명의 채집·제작·운반 분담과 산출물 검증 | 작업 변경·중단·접속 종료·소유권 충돌 복구 |
| G3 여러 AI 협업 | AI 2개가 작업 분담·결과 인계 | 인간 1명·AI 2개 이상으로 공동 격파 |

기본 평가 제안은 새 월드·초기 자원 없음·Normal·keepInventory=false다.
시드·규칙·버전·예산을 시작 전에 고정하고 치트·지급·순간이동·숨겨진 구조물 좌표 조회 없이 진행한다.
준비 월드 시험과 전체 자율 진행을 구분하며, 감독 지시·긴급 중단·수동 복구·자원 제공은 개입으로 기록한다.
사망 후 자력 복구는 허용하되 사망·복구 시간·손실을 남긴다. 실패 시드를 결과에서 제외하지 않는다.
승리는 같은 월드·실행의 드래곤 사망 이벤트/상태로 확인하고 귀환은 별도 기록한다.
보스바 소실·모델 선언만으로 성공 판정하지 않으며 팀 승리와 AI의 기여를 구분한다.

## 단독 플레이 단계

| 단계 | 기능과 주요 작업 | 의존성 | 통과 기준 |
|---|---|---|---|
| S0. 실행 기반 고정 | 현재 재탐색 분기 검증, capability/관측 버전 협상, 취소·사망·재접속 검사 | 현재 코드 | 의도한 분기를 실게임 재현하고 오래된 명령의 재실행·취소 오인 없음 |
| S1. 인벤토리와 제작 | 슬롯 선택, 도구 장착, 아이템 사용, 2×2/3×3 제작, 작업대 설치·접근, 상자 입출고 | S0 | 원목→판자→작업대→나무 도구→돌 도구; 재료 감소와 산출물 증가 일치 |
| S2. 이동·지도·거점 | 1블록 단차, 안전한 내려가기, 수영, 구간별 경로, 배치·굴착, 횃불·침대·귀환 위치 | S0, 배치는 S1 | 다른 지형의 자원 지점 왕복, 길 막힘 재계획, 미로드/낙하 위험에서 중단 |
| S3. 생존 유지 | 식량 획득·조리·먹기, 체력·허기 우선순위, 야간 대피, 사망·리스폰·장비 회수 | S1, S2 | 제안 기준 30분×3회 생존 시험; 긴급 회복·대피·사망 복구를 각각 검증 |
| S4. 장비와 일반 전투 | 광물 채굴·제련, 철 도구/방어구/방패/물 양동이, 근접 공격·막기·활 조준·후퇴 | S1–S3 | 준비 전투장에서 대상별 승패 검증, 도구 파손·탄약 부족·다수 적에 후퇴 |
| S5. 장시간 목표 관리자 | 자원 의존 그래프, 식량/도구 예비량, 체크포인트, 실패 분류, 모델 호출 예산 | S1–S4 | 채집→제련→장비 제작→보급을 개입 없이 연결, 프로세스 재시작 후 상태 대조·재개 |
| S6. 네더 왕복과 재료 | 포털 건설·점화, 차원별 지도, 귀환 경로, 네더 탐색·블레이즈 전투·막대 획득 | S2–S5 | 오버월드에서 준비해 네더 재료를 얻고 귀환; 포털 재진입 및 자원 부족 복구 |
| S7. 엔더의 눈과 요새 | 엔더 진주 확보, 블레이즈 가루·눈 제작, 투척 방향 관측, 장거리 이동, 요새·포털 방 탐색 | S5, S6 | 숨겨진 좌표 없이 요새 도달; 사용·분실·회수·프레임 충전량을 추적하며 포털 활성화 |
| S8. 엔드 전투 단위 스킬 | 진입 지형 확보, 공허 회피, 크리스털 공략, 드래곤 단계 관측·공격·회복·후퇴 | S3, S4; 전체 진입은 S7 | 준비된 시험 월드에서 각 전투 스킬과 드래곤 처치 확인; 장비 지급 사실 명시 |
| S9. 전체 자율 격파 | 새 월드에서 S1–S8 연결, 사망 복구, 전투 실패 후 재보급, 최종 승리 판정 | S5–S8 | G1의 첫 성공 후 고정된 미학습 시드 평가와 비용·개입 보고서 작성 |

S1·S2는 작은 단위로 교차 구현한다. S8 준비 전투는 S4 이후 가능하지만 자연 진행을 대체하지 않는다.
자원 의존 경로는 원목·돌 도구→식량·철 장비→네더→블레이즈 재료·진주→엔더의 눈→요새→엔드다.
탐색 중 소모·분실·예비 자원도 계산한다. 진주 획득 방식과 네더 진입 장비는 실험 후 결정한다.
첫 전투는 활·근접 공격·회복·안전 이동을 기본으로 하고 특수 공략은 별도 평가한다.
크리스털·철창·넉백·공허·엔더맨 적대를 개별 시험하며 다이아몬드 풀세트·자동 농장은 필수 전제로 두지 않는다.

## 목표 구조와 공통 규약

현재 Fabric→브리지→Python 기반 위에 목표 관리자, 관측 지도, 복구 저장소, 협업 조정기와 평가기를 확장한다.
모델은 목표·스킬 선택을 담당하고 회피·낙하 대응·입력 해제 등 짧은 반응은 로컬 제어기가 처리한다.
지도는 이동 중 직접 관측으로 만들고 미관측 공간은 unknown으로 유지한다. 평가용 서버 계측은 계획 입력과 분리한다.

- 스킬별 ID·버전·입력·capability·선행 조건·성공 증거·실패·취소·예산을 정의한다.
- 상태 변경 요청은 실행 ID·대상 상태와 연결한다. 응답 유실 후 재요청 전에 인벤토리·월드를 대조한다.
- S5에서 목표·단계·예산·확인 상태를 트랜잭션 저장소에 보존하고 JSONL은 분석 이력으로 유지하는 방안을 검토한다.
- 행동·시간·재시도·모델 호출·토큰·비용 상한을 스킬/개체/팀/전체 실행에 둔다. 비용은 측정값으로 정하고 초과 시 중단한다.
- 재접속·죽음·차원 이동 때 오래된 행동·지도를 무효화하고 재보급·귀환을 다시 계획한다.
- 실패 분석→수정 제안→격리 시험→버전 등록을 따른다. 생성 코드 즉시 실행·자동 배포는 첫 격파의 필수가 아니다.

## 협업 단계

| 단계 | 구성과 기능 | 의존성 | 완료 기준 |
|---|---|---|---|
| M0. 서버 호환 | 원격 서버에서 단일 Fabric AI, 지연·리스폰·차원 전환·접속 종료 | S0–S2 | 같은 기본 스킬이 서버 확정 상태로 판정되며 서버와 클라이언트 상태 불일치를 복구 |
| M1. 인간+AI 작업 | 인간 요청의 구조화, 범위·수량·납품 지점, 수락/진행/완료/중단, 따라가기·합류 | M0, S1–S3 | 인간이 나무를 요청하면 AI가 정해진 수량을 전달하고 양쪽 수량 변화 확인 |
| M2. AI+AI 분업 | 개체별 실행기, 공유 작업판, 역할·자원 예약, 상자 인계, 충돌·중복 채집 방지 | M0, S1–S3 | 채집 AI와 제작 AI가 공동 산출물을 만들고 담당 접속 종료 시 남은 작업을 인계 |
| M3. 혼합 팀 임무 | 인간+복수 AI, 우선순위 변경, 대피·구조·호위·보급, 공유 지도 | M1, M2, S4–S6 | 원정 도중 역할 변경·장비 손실·한 개체 이탈에도 팀 목표를 재계획 |
| M4. 공동 드래곤 격파 | 자원 분담, 포털 집결, 전투 역할, 팀 체력·탄약·부활·복귀 계획 | M3, S7–S9 | 드래곤 사망과 개체별 기여·사망·개입·비용 기록; 팀 승리와 단독 능력 구분 |

S1–S3가 안정되면 통제된 전용 서버에서 M0–M2를 병행한다. 계정·서버 접근과 여러 클라이언트의 자원 요구도 확인한다.
초기는 AI마다 Fabric·agent·bridge·토큰·로그를 분리하고 상위 조정기가 작업을 할당한다.
현재 단일 브리지에 클라이언트를 추가하는 것만으로 다중 AI가 되지는 않는다.

식별자는 server/world/dimension/agent/player/session/execution/task를 구분하고 플레이어별 입력 소유자를 하나로 둔다.
작업 상태는 제안→수락→예약→진행→검증→완료이며 취소·실패·만료를 별도로 관리한다.
요청자·담당자·영역·수량·납품 위치·기한·버전·증거를 기록하고 예약에는 만료·갱신을 둔다.
상자·작업대·광맥·통로 예약은 실제 게임 상태를 잠그지 않는다. 인간 개입이나 상태 불일치 시 재계산한다.
인계는 준 쪽 감소와 받은 쪽 증가를 모두 검증하고 공유 관측에는 출처·시각·차원·확인 수준을 붙인다.

채팅·책·표지판은 관측 데이터다. 등록된 요청자와 명시적 명령 채널을 통해 작업을 수락한다.
자원 소유권·보호 구역·대인 공격·철거 범위를 정하고 개인 중단과 팀 중단을 구분한다.

## 평가와 위험 관리

단위·합성, 게임 통합, 장시간 단독, 협업, 장애 주입을 나누어 시험한다.
초기 스킬 품질 목표는 대표 조건 10회 중 9회 성공이며 안전한 거절은 별도 집계한다. 통계적 보장 수치는 아니다.
성공률·실패 단계·시간·행동/재시도·호출/토큰/비용·사망·개입을 기록한다.
협업에는 중복 작업·인계 불일치·대기·예약 충돌·개체 기여를 추가한다.

주요 위험은 근거리/높이 제한, 모델 지연, 재시작 상태 유실, 차원 변화, 재시도 비용, 자원 충돌과 특정 시드 편향이다.
각각 도달 스킬·로컬 대응·체크포인트·상태 무효화·공통 예산·예약/인계 검증·고정 평가군으로 대응한다.
1.21.1의 실제 상호작용과 서버 동기화를 회귀 조건으로 고정한다.
공개 자료에는 합성·비식별 재현만 남기고 원본 월드·계정·채팅·좌표는 로컬에 보관한다.
